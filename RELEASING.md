# Releasing

Features go to a release branch for the next version (`release-1.6`), not to main. To release it, move main to that branch: once CI passes on main, the Release workflow publishes 1.6.0 once you approve its run in the `release` environment (Settings > Environments). Every release, a manual one too, waits for that approval. `scripts/which-release.sh` checks that main is at a release branch whose version isn't out yet, and that the release branch got there before main did, so other changes on main (refactors, tests, CI) release nothing. Take a fix from main into a release branch with a merge commit (`git merge --no-ff main`), never a fast-forward: a release branch fast-forwarded to main has nothing of its own and doesn't release. Push the release branch first, then main in a second push: one push of both leaves no way to tell which came first, so it releases nothing. For a patch, open Actions > Release > Run workflow on main and type what goes up: patch, minor or major. If a release branch's own release went missing (main moved on before its CI ended), type its name, `release-1.6`. When main is at a release branch whose version isn't out, a run by hand releases that version whatever you type. `scripts/next-version.sh` works out the version from the last tag, `scripts/build-ipa.sh` builds `Tether.ipa`, `make_source.py` writes `source.json`, and the workflow publishes both as a GitHub release, which creates the tag. The notes come from `scripts/release-notes.sh`: each issue a commit since the last release fixes, by a line starting `Fixes #N`, if the issue is closed as completed and isn't labelled tests, ci, dependencies or documentation. Reverts don't count. So every change people can see needs a `Fixes #N` line, work taken out of a release reopens its issue, and work put back needs a new `Fixes #N` line. `python3 scripts/test_make_source.py`, `scripts/test-next-version.sh`, `scripts/test-which-release.sh` and `scripts/test-release-notes.sh` test the scripts. When you start a release branch, point the Go entry in `.github/dependabot.yml` at it, so Go bumps ship with the next release.
